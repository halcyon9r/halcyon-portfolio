SQL injection

An attack surface counted, then closed

The codebase had about 166 parameterized statements against thousands of concatenated ones. I mapped every site with a script, then closed them with scripted code transforms across 400 to 500 files per application. Each batch was checked by automated review and regression tests before it shipped, which is how one engineer could do it without stopping the business.

10 of 10applications behind a fail-closed access gate

Access control

Broken access control fixed across the fleet

Menus were hidden from unauthorized users, but any account could open any module by URL, finance screens included. More than 120 print and export endpoints per application answered without a login. I built a folder-level gate that denies by default, then rebuilt permissions for 118 users from a 22,000-row legacy table.

RCEunauthenticated file upload, closed

Remote code execution

Upload endpoints locked down

File importers were reachable without a login and saved uploads under their original names in web-served folders. The fix added authentication, strict allowlists and safe renaming, and disabled script execution in every upload directory. I validated it with real multipart uploads.

301klog lines hunted after a critical PHP disclosure

Vulnerability response

Remote code execution in PHP, assessed within a day

When a critical PHP vulnerability came under active exploitation, I confirmed which builds on the production server had received the fix, found the unused interpreter versions that had not, and searched the access logs for exploitation attempts. There were none. The end-of-life runtime only had a partial upstream fix, so I added a configuration mitigation and wrote the plan to move every application to a supported version.

3regression classes traced to root cause

CSRF

A global CSRF layer, and the regressions it caused

Per-session tokens with automatic AJAX injection and central verification. The rollout broke a few pages in ways that were hard to see: tokens truncated on very large forms, and a report page that reloaded its JavaScript library and dropped the token handler. I traced each one and fixed it on every application.

AI engineering

Agents with real permissions, deployed carefully.

I treat an AI agent on a company server like any other software that can break production. It gets audited, scoped and monitored before it gets access.

Deployment

Coding agents on enterprise servers

Before an agent runs on a corporate host I check the operating system and hardware requirements, open a single outbound API endpoint through the firewall, and set up non-interactive authentication so no personal login ever sits on a production machine.

Review

Multi-agent code review

One group of agents looks for defects and a second group tries to disprove each finding, so only verified problems reach a human. A single review has run 28 agents, and one caught 22 real bugs in a service before release. The same setup verified the hardening work across the ten-application fleet described above.
